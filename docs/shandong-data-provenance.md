# 山东区域数据来源与维护说明

更新日期：2026-10-28。本文为内部维护记录，不在业务页面展示。

## 数据边界

行政区划、城市名称和地图轮廓采用公开地理资料。企业运营、车辆任务、运行轨迹、安全事件、信用和评价记录属于合成业务初始化数据，用于本地功能开发与联调，不是实际车企生产接入记录，不应被用于对真实主体作出行政或信用结论。

运营企业名称在迁移时统一换为构造的业务主体名称，避免将原安全事件、违规或评价关联到真实企业。厂商车型仅作为参考目录；未经核验的厂商地址改为“企业资料待核验”。联系人和业务编号也属于初始化内容。

按用户要求，业务页面不出现“模拟、示例、演示”等环境标签。来源性质在本文件及迁移脚本中保留，不把固定回执或合成事实包装成真实厂商接入。

## 迁移行为

- 执行前 SQLite 在线备份：`tmp/backups/regulatory-before-shandong-saas-20261028.db`，原始约 7 MB。保留在工作区，不随代码交付公开。
- `prisma/migrate-shandong.ts` 保留企业、车辆及原有业务记录 ID，并按企业归属重新绑定组织、许可、运行、告警、事故、信用等记录。
- 保留 16 市区划与地理参考。只开通已有业务的济南、青岛、临沂三个城市，其他地市可通过公开申请流程开通。
- 当前保留 12 家企业、348 辆车辆。济南4家/65辆，青岛4家/115辆，临沂4家/168辆。迁移共转换 10,616 行既有记录，详细执行结果保存在 `tmp/shandong-migration-result.json`。
- 轨迹和区域采用确定性坐标变换：保持既有局部形状及点序列，压缩并平移到所属山东城市/区县附近，不属于真实道路采集数据。跨市的旧区域车辆分配被移除，运行记录关联到本市区域。
- 原有时间序列按相对天数迁移到当前业务周期；当前定位心跳写入迁移时点附近。没有运行独立的车端实时上报源。
- `prisma/enrich-shandong.ts` 为三个城市补充彼此关联的许可、七日在线统计、安全核查、应急处置、企业评价、监管报告、安全员及接入配置。
- 接入配置保留 `UNVERIFIED`，地址属于待接入配置，不代表真实生产网络连通。其界面与配置检查不得宣称实际厂商接入成功。
- 全国地图保留其他省份地理名称；除山东外的业务统计清零，旧浙江城市业务目录移除。
- 已开通城市均使用本市独立角色与流程副本；全省管理员不与城市管理员混用。

## 初始化命令

- `pnpm db:seed` 建议指向 `tsx prisma/seed-shandong.ts`：仅对用户、企业、市级申请都为空的全新库调用基础初始化；对已有数据库只进行增量迁移和关联补全，不重置城市申请或人员。
- `pnpm db:shandong` 建议依次执行 `tsx prisma/migrate-shandong.ts` 与 `tsx prisma/enrich-shandong.ts`。
- 原 `prisma/seed.ts` 保留为全新库内部初始化步骤，不应单独用于已有环境，否则其原有重置语义会删除业务记录。
- 迁移版本存于济南工作空间 `configJson.dataMigration`；重复执行会跳过位置与日期平移，避免二次迁移漂移。
- 新企业、城市申请及权限操作不能仅靠迁移版本标记视为初始化数据；后续人工建立的记录不由增量补全删除。
