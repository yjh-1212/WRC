# 省域运行分析设计

日期：2026-10-29。范围：产品与视觉设计图，不修改业务页面。图片使用示例数据。

设计图：`01-province-analysis.png`。已检查导航命名、查询区、指标带、同单位趋势图、三市对比与汇总表，图内没有地市履责评分。

## 页面定位

省级监管人员按统计周期观察运行规模、变化趋势与地市差异，再进入某市分析。入口为“统计分析 / 省域运行分析”，同组保留“监管报告”。不包含地市履责评价、评分、等级或履约排名。

## 页面结构

1. 查询：日期范围、近7日 / 近30日 / 本月、已开通地市、运营企业；查询与重置。默认完整的近30日，截止昨日。
2. 概况：一条紧凑指标带，展示运行车辆、累计里程、运行次数、累计运行时长、自主运行里程占比和累计能耗。标注统计范围与数据时间。
3. 趋势：主体区域为按日运行趋势，切换里程、次数、时长；上期同长度时间段映射到本期日期位置，用虚线对照，提示框显示双方实际日期。不同量纲不共用一个数轴。
4. 地市对比：按稳定地市顺序展示累计里程和占比，点击地市联动明细，不使用评价或名次。
5. 明细：地市、运营企业数、运行车辆数、次数、里程、里程占比、自主运行里程占比、百公里能耗；保留全省汇总和查看分析入口。

## 交互与口径

- 地市切换后，运营企业可选范围随之变化；所有指标、图表、明细共用相同查询条件。筛选提交后更新，重置恢复默认范围。
- 查看分析先进入同一页面的城市范围，显示可取消的城市条件，再查看企业；单车放到继续下钻层，不放在省域首屏。
- 导出按当前筛选全量导出，包含查询条件、统计时间和口径。监管报告沿用相同期间进入已有报告流程。
- 运行车辆按周期有记录的车辆去重，区别于在册车辆；运行次数沿用当前运行记录条数口径。
- 自主运行里程占比＝自主里程 / 总里程；百公里能耗＝累计能耗 / 总里程 × 100；总里程为0时展示“—”。
- 全省比率按汇总分子、分母计算，不平均各地市比率；全省车辆、企业按主体去重，不无条件相加。
- 环比使用前一等长周期；上期为0时展示“无可比基数”，不生成无穷增长率。图上以变化描述为主，不将增长一律视为优秀。
- 未上报、未接入、无记录与加载失败区分；部分来源缺失时标明缺失范围，不将其计为0。失败保留筛选并提供重试。
- 视觉沿用现有省级平台的横向导航、浅灰画布、白色面板和蓝色重点色；不用驾驶舱大屏风格。

## 已有能力与实施缺口

依据：`apps/web/src/views/OperationsAnalysisView.vue`、`apps/api/src/analytics/analytics.service.ts` 的 `operationAnalysis`、`AnalyticsQueryDto`、现有省级菜单及全省监测设计稿。

- 已有：期间 / 企业 / 车辆过滤，运行车辆去重、次数、里程、时长、能耗、自主里程比例，按日趋势和企业 / 区域聚合。
- 需扩展：按工作空间汇总地市、地市企业联动、上期对比、运行分析明细导出。虽然查询DTO已有workspaceId，地市聚合及层级归属仍需核对实际服务数据范围。
- 需验证：企业与车辆跨市去重规则、运行记录完整性、数据截止时间与接入覆盖情况。图片不代表已完成这些能力。
- 当前“运行效率”计算实际为平均运行速度（km/h）；本次首屏不将其作为综合效率或履约指标。
