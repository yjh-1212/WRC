# 省级统一部署、市级申请开通：开发任务清单

日期：2026-10-28。状态：待实施任务清单，未代表功能已经实现。

## 1. 建设范围

依据本次讨论，建设一套省级统一部署的平台。市级申请开通后获得独立城市工作空间，通过统一网址登录，管理本市组织、人员、企业和业务；省级按监管授权查看跨市情况。

本期完整链条：市级申请 → 省级审核 → 城市授权 → 系统开通 → 管理员激活 → 登录本市 → 分配权限 → 使用现有业务。

三个独立控制层：城市功能授权、人员操作权限、业务数据范围。一次业务操作必须同时通过三层校验。

建议的首期边界：

- 一个城市一个工作空间，市内部门和区县属于内部组织，不分别建设租户。
- 普通市级账号首期固定所属城市；多人多城市任职的切换机制后续扩展。身份与城市成员关系仍分开建模。
- 企业保留统一主体身份，以城市入驻/业务关系关联各市；许可、申请、车辆属地关系和处置记录按归属管理。是否允许同一车辆同时在多市运营，需要在 T01 确定规则。
- 城市间业务数据隔离。共享字典、厂商车型等参考数据需单独定义共享范围，不能把全部对象都机械复制为城市私有数据。
- 共用数据库可作为首期技术方案候选，采用明确城市归属和后端校验；逻辑数据隔离不等于每个城市独立数据库。
- 先建设功能授权与期限管理。在线支付、自动计费、多级分销、独立城市域名及城市独立部署不列入首期。
- 跨市材料互认、国家平台对接等属于后续业务建设，本清单仅预留授权边界，不混入本次基础改造。

## 2. 优先级与角色

- P0：正式开放城市前必须完成，包含隔离基础、申请开通、账号分权及验收。
- P1：可以在受控试点后完善；若上线时启用对应业务规则，则必须先完成其行为与测试。
- 责任类型：产品、后端、前端、数据、测试、运维。实际负责人和工期在排期时指定。

## 4. 推荐实施顺序与阶段出口

| 阶段 | 主要任务 | 阶段出口 |
|---|---|---|
| 第一阶段：模型与隔离基础 | T01-T10；T25 同步建设 | 两个测试城市的全模块接口能证明数据隔离，省级可按授权查看，市级不能越权授权 |
| 第二阶段：申请与开通 | T11-T16 | 一个城市可从申请走到开通成功，失败可恢复，管理员可激活 |
| 第三阶段：使用与治理 | T17-T21、T24；补足审计 | 市级可登录、配置本市人员并使用原业务；交接和撤权生效，原业务不串市 |
| 第四阶段：验证与试点 | T28-T30 | 完成两城市隔离、全流程和业务回归，迁移恢复可验证后再开放 |
| 后续完善 | T22、T23、T26、T27 | 提升自助开通、变更申请、通知和运行管理能力 |

T28-T29 的用例应在开发时编写并随任务执行，阶段四是汇总验收，不把隔离测试推迟到最后。T25 从第一阶段开始；其依赖只是首个可实施入口。

## 5. 最小验收场景

1. 济南申请、退回补正、重新提交、省级批准，开通成功，管理员激活进入济南工作台。
2. 青岛独立开通，人员、角色、本地配置及业务记录不受济南开通或角色变更影响。
3. 济南人员替换详情、附件、导出和批量接口中的 ID，均不能读取或操作青岛业务。
4. 济南区县人员只能在被授权辖区办理事项；本市企业账号不能查看本市其他企业的私有业务。
5. 省级监管按授权下钻济南或青岛；运维身份未获业务授权时不能读取业务明细。
6. 城市未开通某模块时，直接调用接口仍被拒绝；批准开通后按人员权限使用，撤回后旧会话失效。
7. 两个并发请求尝试取消本市全部管理员时，至少保留一位有效管理员；失联恢复留有核验及操作记录。
8. 审核重复点击、开通中断、重试、邀请过期及重发不产生重复城市、重复授权或错误管理员。
9. 到期/暂停/恢复严格符合已确认策略；重要数据保留，界面与接口行为一致。
10. 原杭州数据迁移后总量、关联及归属一致；数据备份可以恢复。

## 7. 排期前需要落实的输入

| 输入 | 建议责任方 | 处理方式 |
|---|---|---|
| 城市申请单位和首位管理员如何核实 | 省级业务负责人 | T01 确认材料与核验规则；未核实不授正式城市权限 |
| 省级可查看的明细及运维访问边界 | 省级业务负责人、平台负责人 | T01 权限表明确；不以平台超级管理员代替监管授权 |
| 到期、暂停及安全处置保留范围 | 省级业务负责人 | T01 决定，T24 实现后才能启用自动状态变化 |
| 企业跨市、车辆属地与迁移规则 | 产品、业务负责人 | T01 决定，T02-T03 执行；不自动合并或转移既有业务 |
| 邀请通知渠道及送达能力 | 平台负责人 | 首期可采用可撤销激活邀请与申请状态页；外部渠道未接入时不宣称已发送 |
| 现有数据库是否继续用于正式部署 | 技术负责人、运维 | 结合实际城市数、遥测量、并发和备份恢复需求评估；不把 SQLite 本地运行等同于生产容量验收 |

本清单用于拆分研发工作；未执行数据迁移、开通城市、授予权限或修改现有业务代码。工期需要结合人员、对象归属盘点和数据库部署选择后评估。
