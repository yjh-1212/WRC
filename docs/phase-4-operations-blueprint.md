# Phase 4 运行监管蓝图

## 交付结论

Phase 4 在既有 Vue 3 + NestJS + Prisma SQLite 工程中增量完成，没有重建项目、替换技术栈或修改前三期迁移。范围依据《无人快递车监管平台需求说明书》车辆运行监测、运行记录、轨迹管理和运行区域管理章节，以及总提示词 Phase 4 固定清单。

本阶段覆盖车辆实时状态、运行记录、实时运行地图、车辆分布、在线监测、车辆轨迹、轨迹回放和运行区域。地图使用高德 JSAPI v2.0；车辆坐标、轨迹和区域边界全部来自后端 API 与数据库，不在 Vue 文件中硬编码业务数据。

## 业务结构

监管端“运行监管”包含 6 个独立任务入口：实时运行、车辆分布、车辆轨迹、运行记录、在线监测、运行区域。企业端不照搬监管端，仅提供实时车辆、车辆轨迹、在线情况和运行记录；企业页面与 API 均强制限定当前企业。

```text
车辆遥测接入 → 实时状态快照 → 实时地图 / 在线监测 / 分布研判
       └────→ 运行记录 → 轨迹点 → 轨迹查询与回放

审批结果 → 已批准运行区域 → 关联企业与车辆 → 地图 Polygon 与区域规则
```

## 数据模型

| 模型 | 责任 |
| --- | --- |
| `VehicleRealtimeStatus` | 单车最新位置、速度、方向、电量、驾驶模式、信号和心跳 |
| `OperationRecord` | 一次连续运行的时间、区域、里程、速度、能耗和状态台账 |
| `VehicleTrackPoint` | 运行记录下的有序轨迹点，保留停留点和状态事件类型 |
| `VehicleOnlineDaily` | 车辆每日在线分钟与在线率，支撑近 7 日趋势 |
| `OperationRegion` | 获准运行范围、生效期、审批状态、限速时段和规则 |
| `OperationRegionVehicle` | 运行区域与获准车辆的多对多关系 |

增量迁移：`20260902151212_phase4_operations`。Seed 写入 30 辆车的实时状态、30 条运行记录、960 个轨迹点、7 天在线指标和 4 个运行区域。

## 状态与口径

- 连接状态：`ONLINE`、`OFFLINE`，由车辆最新遥测更新。
- 运行状态：`RUNNING`、`IDLE`、`PARKED`、`OFFLINE`。
- 自动驾驶状态：`AUTO`、`MANUAL`、`REMOTE_TAKEOVER`、`STANDBY`。
- 运行记录：`RUNNING`、`COMPLETED`、`INTERRUPTED`。
- 运行区域：审批状态与启用状态分离；只有 `APPROVED` 区域可启用。
- 当前在线来自车辆连接状态；今日上线来自当日在线指标；近 7 日在线率按车辆日指标平均计算。

## 地图图层与交互

地图遵循“业务主图层优先、上下文底图降噪”的层级：

- 实时运行：原生 Marker 表达运行、在线停驶、低电量和离线；车辆列表、Marker、信息窗和详情联动；叠加已启用运行区域。
- 车辆分布：同一业务任务内切换散点、MarkerCluster 聚合和 HeatMap 热力图；侧栏同步展示企业、行政区与状态分布。
- 车辆轨迹：Polyline、方向箭头、停留/事件点和 MoveAnimation 回放；速度变化与关键节点共用同一轨迹结果。
- 运行区域：Polygon 表达审批与启用状态；地图与区域列表联动。
- 生命周期：安全配置先于 Loader；固定使用 JSAPI 2.0；创建地图前写入技能 appname；组件卸载时清理覆盖物并销毁地图实例。

地图密钥只保存在被忽略的 `apps/web/.env.local`。生产环境支持 `VITE_AMAP_SERVICE_HOST`，用于通过服务端代理保护安全密钥。

## API

统一前缀 `/api/operations`：

- `GET /options`：按范围返回车辆、企业、机构、区域和可关联审批结果。
- `GET /realtime`：实时车辆、状态摘要和地图点位。
- `GET /distribution`：地图点位及企业、行政区、状态聚合。
- `GET /online-monitor`：当前/今日在线、7 日趋势、企业在线率和异常企业。
- `GET /records`、`GET /records/:id`：运行记录分页、筛选与全过程详情。
- `GET /vehicles/:vehicleId/tracks`：按运行记录或时间范围查询统一轨迹。
- `POST /telemetry`：更新实时状态，并可向指定运行记录追加轨迹点。
- `GET/POST /regions`、`PATCH /regions/:id`、`PATCH /regions/:id/status`：区域查询、维护和启停。

## 权限与数据范围

- 监管超级管理员查看全量；其他监管角色查看本组织与直属下级组织。
- 企业账号的服务端查询固定追加 `enterpriseId`，请求参数不能扩大范围。
- 企业端没有车辆分布和运行区域菜单；区域只作为实时地图依赖只读返回本企业已关联范围。
- 企业管理员拥有遥测接入权限，企业普通用户只读；企业账号不能维护已批准运行区域。
- 运行区域写入会校验管理机构、关联企业和车辆的数据范围，跨范围或企业车辆不一致返回 403。
- 区域创建、修改和启停写入审计日志；高频遥测不逐条写审计日志，避免审计表成为时序数据副本。

- 构建：`pnpm run build`。
- API：实时 30 辆、运行中 7 辆、30 条运行记录、4 个区域、7 天趋势与 1 条审批关联均验证。
- 浏览器：`node .agents/skills/playwright-skill/run.js tests/e2e/phase4.cjs`。
- 截图：`test-results/phase4/`。
- 关键断言：监管端 30 辆、企业端 10 辆且只有一个 `enterpriseId`；散点/聚合/热力切换；轨迹 32 点与回放；记录详情复用轨迹地图；在线趋势 7 天；4 个区域 Polygon；企业端无监管专属菜单；390px 窄屏无页面级横向滚动。

## 外部配置项

当前截图提供的 Web 端 Key 与安全密钥已按本地密钥文件接入，高德 JSAPI、控件和业务覆盖物可以运行。浏览器同时收到高德鉴权返回的 `INVALID_USER_DOMAIN`，因此本机 `localhost` / `127.0.0.1` 的底图样式数据被控制台域名白名单拒绝。需要在高德开放平台对应 Web 端 Key 的“设置”中加入本地开发域名（以及最终部署域名）后再做底图最终验收；此项不能通过前端代码安全绕过。

## 后续阶段复用

Phase 5 的告警、事故、电子围栏触发和事故回溯应复用本期 `VehicleTrackPoint` 查询、Polyline 与回放组件，不再新建轨迹子系统。运行区域是获批业务范围，电子围栏是安全规则边界，两者保持独立模型和生命周期。
