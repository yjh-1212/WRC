# 市级监管工作台开发与验收

日期：2026-10-31

## 已实现

按用户确认的第二版设计开发 `/regulatory/overview`。移除原顶部汇总卡、监管待办大面板和辅助地图，采用三排布局：

1. 运行趋势、车辆运行状态、安全事件分析。
2. 无人车类型分布、车辆厂商分布、辖区车辆分布。
3. 企业运行统计、少量待办提醒。

沿用现有中国数联品牌与居中文字导航。运行趋势支持里程／次数切换，日期支持今日、近7日、本月及自选范围，并通过URL保存范围。图表保留坐标、单位、图例及完整日期序列。企业表支持翻页及右侧详情，待办带筛选条件进入业务页，监管驾驶舱保留入口，通用AI对话可正常打开。

车辆类型列出配送、环卫、巡逻、零售、接驳五类，并保留未知类型的“未分类”。尚未接入的类型显示0；圆环中心统计实际已接入的非零类型数，不把可选分类数量当作接入数量。厂商从车辆所属车型的生产厂商统计，与运营企业分开。

## 接口与口径

- 新增只读 `GET /api/dashboard/regulator/workbench?from=YYYY-MM-DD&to=YYYY-MM-DD`。
- 使用已验证的机构范围；市级按 `scopeOrganizationIds` 限定；省级指定城市视域同样限制原生SQL聚合。企业及运维账号不能访问该监管接口，各子模块按权限返回数据或不可用状态。
- 当前车辆快照来自未删除车辆档案。运行车辆必须同时上报在线及RUNNING；离线车辆的旧RUNNING状态不会重复计为运行中。该快照反映最近上报状态，不宣称独立实时探活。
- 类型、厂商、辖区统计与车辆总数使用同一数据集合；占比按各分类车辆数／总车辆数计算。厂商未登记、未知类型保留对应兜底分组。
- 运行统计按北京时间运行开始日期归集已入库运行记录，服务器按企业及日期分组。查询范围内的空日期保留为0；负值等异常里程保留为待核对，不伪造为零或插补曲线。跨天行程全部归入开始日。
- 日期限1至366天，不允许无效日期、倒置区间或晚于当天的结束日期。默认本月1日至北京时间当天。
- 安全统计包含当前账号可读的告警、事故、违规及离线事件。可读的类型化子事件替代来源告警，避免重复统计；CLOSED、ARCHIVED、RECOVERED归闭环，其余分别归待核查和处置中。待复核属于处置中的子状态。
- 安全事件及运行记录随日期筛选；车辆、类型、厂商、辖区和待办是当前快照，不因切换历史日期而伪装成历史车辆存量。
- 业务待受理按SUBMITTED统计，整改待复核按整改任务PENDING_REVIEW统计，临期许可按未来30天内有效许可涉及的车辆去重。
- 页面不硬编码设计图数值，不增加业务记录或模拟分布。无需数据库迁移或安装依赖。

## 验证

- API TypeScript无输出类型检查通过。
- 前端生产构建通过；保留原有大体积bundle提示。
- 后端全套26个测试集、184项测试通过。新增6项统计专项测试覆盖北京时间、无效区间、零记录日期、异常里程、分类兜底、城市隔离、权限拒绝、离线旧状态、事件去重及临期车辆去重。
- 可见浏览器与真实API／数据库回归通过，当前城市车辆65辆、厂商4家；当前车辆全部属于配送，其他类型为0。与数据库逐日运行记录、企业总数及事件处置队列交叉核对一致。
- 验证了日期和趋势指标切换、URL刷新恢复、空日期范围、失败重试、企业详情、通用AI对话、待办／临期跳转，以及1920×1080、1440×900和390×844布局。
- 1920×1080统计区在一个视口内显示，企业四行完整可见；窄屏允许自然纵向滚动，企业表内部支持横向滚动，不造成整页横向溢出；当前所有厂商行完整展示。
- 测试不新增或修改车辆、档案、运行、安全事件等业务数据；登录产生正常认证审计记录。

运行专项回归：`pnpm test:e2e:city-workbench`。首次需本地API与Web开发服务已运行，可用 `API_URL`、`TARGET_URL`、`TEST_PASSWORD` 覆盖验收环境配置。
